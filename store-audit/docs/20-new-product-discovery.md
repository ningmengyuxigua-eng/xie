# 新品發現與商品增量同步

## 現況

- 2026-10-06探索快照有1,338個商品。
- 現有SQLite的`product_master`及`product_observations`尚未正式匯入商品基線。
- 因此新品同步的第一步是匯入既有1,338個商品，再比較後續商品清單中的`product_id`。

## 新品判斷

唯一判斷Key：`store_id + product_id`。

- 商品ID第一次出現：`new_product`。
- 已知商品重新出現：更新`last_seen_at`，不是新品。
- 商品改名、改SKU或改價格：建立新版本，不能產生新的商品身份。
- 已消失商品重新出現：`rediscovered`，保留原商品身份及歷史。

禁止使用商品名稱、SKU、頁面排序或建立日期作為新品唯一Key。

## 上架時間與生命週期

- 商品真實上架時間保存於`listed_at`，優先取商品詳情API的`first_publish_time`，缺失時才使用`create_time`。
- `first_seen_at`只代表本系統第一次看到商品，不能代替`listed_at`。
- 既有1,338筆本機基線不為補上架時間重新查詢詳情；沒有可信來源時`listed_at`保持空值。
- 舊商品日後因廣告、促銷或人工檢查而自然讀到可信詳情時，可順帶補齊`listed_at`，不另做全店批量回查。
- 新發現商品讀取詳情時，同步寫入上架時間與來源欄位。
- 生命週期狀態固定為`unknown / draft / pending_review / active / suspended / delisted / deleted`。
- 每次狀態改變都寫入`product_lifecycle_event`；下架後保留商品、流量、廣告、促銷與歷史版本，不刪除資料。
- 商品在完整核對中缺失一次只記錄待核對；連續兩次缺失才進人工下架審核，不自動下架。
- 平台明確回傳下架狀態時可立即記錄`delisted`；再次出現則記錄`active`及重新上架事件。

## 同步策略

### 每日快速發現

1. 打開「我的商品」，切到可售／上架商品。
2. 使用平台「以最近排序」；已於2026-10-08驗證其URL/API參數為`modified_time`。
3. 每批只返回20個商品的`product_id`、名稱、SKU、狀態及商品網址。
4. 預設最多讀5批，共100個商品。
5. 未知`product_id`立即寫入新品事件及詳情佇列。
6. 若排序已驗證，可在連續40個已知商品且時間早於上次水位後停止。
7. 已知商品只做ID存在性比較，不重新開啟詳情，也不重寫未變更內容。
8. 排序不能驗證時不得提前停止，改用輪轉頁碼並依靠每週身份核對補漏。

### 每週身份核對

- 全部商品頁只讀商品ID及狀態，不重新讀取舊商品詳情；每批20筆，每輪最多5頁並保存checkpoint。
- 核對新增、重新上架、狀態變更及長期未看到商品。
- 商品一次未出現不能直接標記下架；至少連續兩次完整全量核對未出現才進人工下架核對。

### 新品詳情佇列

新品發現後，不在列表掃描程序中直接讀取所有詳情。先加入佇列，再逐個呼叫已驗證的商品詳情API：

`/api/v3/product/get_product_info?product_id=<product_id>&is_draft=false`

詳情最少保存：

- 商品ID、名稱、主商品貨號及狀態。
- 規格ID、規格名稱、商品選項貨號。
- 目前售價及促銷資訊。
- 庫存欄位（來源確認後啟用）。
- 內容雜湊、首次及最後看到時間。
- 平台首次上架時間、上架時間來源及目前生命週期狀態。

每輪最多處理20個新品詳情；失敗最多重試3次，之後保留佇列狀態等待人工檢查。

## 建議資料表

### `product_discovery_run`

保存快速／全量掃描的run_id、日期、模式、頁碼、看到商品數、新品數、狀態及checkpoint。

### `product_discovery_event`

保存`new_product`、`rediscovered`及`status_changed`事件，Key包含店鋪、商品ID、事件類型和觀察時間。

### `product_detail_queue`

保存待讀詳情的商品ID、原因、優先級、狀態、重試次數及最後錯誤。

### `product_versions`

商品名稱、SKU、價格、狀態或規格實際變更時建立新版本；相同內容雜湊不增加版本。

### `product_lifecycle_event`

保存每次生命週期狀態轉換、有效時間、觀察時間、原因與來源。下架只關閉目前生命週期，不刪除商品主檔及歷史。

## 接入順序

```text
商品發現同步
→ product_master UPSERT
→ 新品事件
→ 詳情佇列
→ 規格／價格／促銷同步
→ 商品流量觀測
→ 廣告與促銷映射
→ 組合／加價購候選
→ 新品及資料品質報表
```

商品發現應排在每日廣告及組合分析之前，確保當天新建立的商品可以被後續模塊識別。

## 2026-10-08增量驗證

- 商品總數由1,338增加至1,357，共19個未知商品ID。
- `modified_time`排序的第一頁48筆已包含全部19個未知ID，因此沒有掃描其餘舊商品頁。
- 19個新品詳情均已讀取完成；`first_publish_time`均為2026-10-07。
- 匯入後商品主檔為1,357筆，詳情佇列為0，資料庫完整性及外鍵檢查通過。

## 報表內容

新品日報預留以下內容：

- 今日發現新品數、詳情完成數及失敗數。
- 商品ID、名稱、狀態、售價區間及是否已有促銷。
- 是否已加入廣告、是否缺少SKU／價格／庫存。
- 是否進入組合／加價購候選。
- 上架日期、商品年齡、生命週期狀態及下架候選原因。
- 最多顯示20個新品；完整清單保存在CSV及資料庫。

## 防漏與防誤判

- 每日快速掃描負責速度，每週全量核對負責完整性。
- 新品以商品ID判斷，不因改名重複建立。
- 頁面讀取中斷時從checkpoint續跑，不清除已完成頁面。
- 新商品不會自動加入廣告或促銷，只進入待審核清單。
