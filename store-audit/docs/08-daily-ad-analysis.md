# 每日廣告有效性分析模組藍圖

## 目標

每天分析台灣時間前一天 `00:00:00–23:59:59` 的廣告結果，判斷進行中的單品廣告及廣告群組是否有效，輸出可執行建議。初期只產生報告，不自動暫停、調整預算或修改 ROAS 目標。

執行節奏採漸進式調整：先觀察D+1與D+3歸因，不批量關閉廣告；需要人工調整時先處理1個，同批最多3個，每次調整後至少觀察3天再處理下一批。

## 現有資料基準

- 廣告總紀錄：1,869
- 進行中廣告：126
- 進行中單品廣告：81
- 進行中廣告群組：45
- 已取得商品明細的進行中群組：42
- 群組商品明細：1,227 列、1,221 個商品
- 待補：3 個進行中群組的商品映射

現有快照使用「上月」區間，只能作欄位及映射驗證；每日模組必須重新按昨日日期讀取。

## 每日處理流程

1. 以 `Asia/Taipei` 計算昨日日期，不使用執行機器的模糊相對時間。
2. 讀取目前狀態為「進行中」的廣告清單，分成單品廣告與廣告群組。
3. 查詢昨日的廣告層指標：曝光、點擊、CTR、花費、加入購物車、轉換、銷售數、銷售額、ROAS、直接轉換及直接銷售額。
4. 只展開昨日有曝光、點擊或花費的廣告群組，再讀取群組中的商品層成效。
5. 用 `store_id + metric_date + ad_id` upsert 廣告日資料；群組商品用 `store_id + metric_date + ad_id + product_id` upsert。
6. 合併商品價格、進行中促銷及成本資料，執行有效性規則。
7. 輸出最多 20 筆需要處理的廣告，其餘保存本地，不灌入對話。
8. 對 D-3 再讀取一次並覆寫同一日期資料，以吸收延遲歸因；保留修訂時間。

## 分析層級

### 單品廣告

- `ad_id` 對應一個主商品。
- 先判斷廣告整體，再與該商品近 7 天、近 30 天自然流量和促銷狀態比較。

### 廣告群組

- 第一層判斷群組總花費與總回報。
- 第二層按 `ad_id + product_id` 找出群組內有效商品、耗費無轉換商品及沒有投放的商品。
- 不用群組總 ROAS 掩蓋個別商品虧損。

### 商品彙總

- 同一商品若參加多個廣告，另外產生商品日彙總。
- 商品彙總只能作決策輔助；原始廣告及群組商品紀錄仍按 ID 保存。

## 核心指標

- 曝光數、點擊數、CTR
- 花費、平均點擊成本 CPC
- 加入購物車數及加購率
- 轉換數、銷售數、轉換率
- 廣告銷售額、ROAS、ACOS
- 直接轉換、直接銷售額、直接 ROAS
- 商品目前售價、是否參加促銷
- 毛利率、損益平衡 ROAS、目標 ROAS（成本資料完成後）

`ACOS = 花費 / 廣告銷售額`

`損益平衡 ROAS = 1 / 扣除平台費與增量物流後的貢獻毛利率`

如果沒有成本，不輸出「盈利／虧損」結論，只輸出流量與轉換效率判斷。

## 判斷狀態

| 狀態 | 判斷方向 | 建議 |
|---|---|---|
| `effective_scale_candidate` | 有轉換，ROAS 高於目標，且直接銷售占比合理 | 候選增加預算，先核對毛利 |
| `effective_hold` | 有轉換，ROAS 接近或高於目標 | 維持觀察 |
| `observe_low_sample` | 曝光、點擊及花費樣本不足 | 不操作 |
| `low_ctr` | 曝光足夠，但 CTR 明顯低於同類廣告基準 | 改主圖、標題或關鍵字 |
| `clicks_no_conversion` | 點擊達門檻但無轉換 | 查價格、促銷、商品頁與受眾 |
| `spend_no_return` | 花費已達可容忍上限但無銷售額 | 候選降預算或暫停 |
| `below_break_even` | 有銷售但 ROAS 低於損益平衡點 | 候選降價出價或停止 |
| `delivery_issue` | 進行中但連續無曝光 | 查預算、競價、審核及庫存 |
| `mapping_issue` | 廣告或群組商品無法對應商品 ID | 先修復映射，不做效果判斷 |

## 樣本與防誤判規則

- 單日報告一定同時顯示昨日與近 7 天背景，不因一天波動直接停廣告。
- CTR 至少累積 200 曝光才判斷；低 CTR 以同廣告類型中位數的 50% 為初始門檻。
- 無轉換至少累積 15 次點擊才進入警告，20 次點擊仍無轉換才列高優先。
- 無曝光需連續 2 個完整日才列為投放異常。
- 預算或停用建議至少需要 2 個完成歸因的異常日，或花費已超過單筆可接受貢獻毛利。
- 直接 ROAS 作為主要商品效果證據；總 ROAS 用來觀察廣告帶來的店鋪連帶銷售。

## 延遲歸因

- D-1 報告標記為 `provisional`。
- 每天同時回補 D-3，若數字改變則 upsert 並標記 `revised`。
- 自動動作只能使用完成回補的資料；初期不啟用任何自動動作。

## 資料表與 KEY

### `ad_master`

- 主鍵：`store_id + ad_id`
- 欄位：廣告名稱、類型、狀態、每日預算、目標 ROAS、首次／最後觀察時間

### `ad_daily_fact`

- 主鍵：`store_id + metric_date + ad_id`
- 欄位：所有昨日指標、資料狀態、讀取時間、修訂時間

### `ad_product_daily_fact`

- 主鍵：`store_id + metric_date + ad_id + product_id`
- 適用：廣告群組商品明細及單品廣告商品映射

### `ad_evaluation`

- 主鍵：`store_id + metric_date + ad_id + product_id_or_zero + rule_version`
- 欄位：判斷狀態、證據、建議、是否需要人工處理

### `ad_sync_run`

- 主鍵：`run_id`
- 欄位：日期範圍、頁碼進度、成功／錯誤數、checkpoint、耗時

## 增量與效能

- 每批最多 20 筆，先讀廣告層，再只展開有投放的群組。
- 原始回應按日期保存，分析只讀壓縮後 JSONL 或 SQLite 日表。
- 使用 upsert，不重複追加同一日期與廣告 ID。
- 對話只展示摘要及最多 20 個異常／機會項目。
- 每月生成廣告與商品彙總；日明細不隨對話增長。
- 長期查詢遵守 `09-scale-and-context-safety.md`：月報讀月彙總，半年報只讀 6 筆月彙總，禁止把完整日明細灌入模型上下文。

## 分階段實作

1. 建立每日資料契約、KEY 與 checkpoint。
2. 建立昨日廣告層增量收集器，先覆蓋 81 個單品廣告與 45 個群組。
3. 補齊 3 個群組映射，只展開昨日有投放的群組。
4. 建立無成本版規則：投放、CTR、點擊、轉換及 ROAS 相對表現。
5. 成本資料可用後加入損益平衡 ROAS 與預算建議。
6. 驗證至少 7 個完整日後，再決定是否啟用定時任務和通知。
