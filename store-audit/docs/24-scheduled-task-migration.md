# 定時任務跨電腦遷移

## 執行原則

Codex 定時任務屬於建立任務的本機環境，不隨 Git 程式碼或 OneDrive 資料快照自動啟用。兩台電腦可以保存相同的任務規格，但任何時候只有 `primary` 主機可以把採集任務設為 `ACTIVE`。

## 目前任務

| 名稱 | 台灣時間 | 用途 |
|---|---:|---|
| 每日廣告分析 | 09:30 | D-1 廣告及 D+3 延遲歸因 |
| 拾味廚房雜貨鋪每日廣告分析 | 09:30 | 廣告增量、7/30日比較與候選下鑽 |
| 拾味廚房雜貨鋪商品零瀏覽巡檢 | 10:30 | 商品卡流量、60日閘門與選品價值 |

## 換主機順序

1. 舊主機將全部任務設為 `PAUSED`，並完成最後一次 SQLite 驗證及 OneDrive 快照。
2. 新主機從 GitHub 取得最新 `main`，從 OneDrive `ShopOps-Backup/latest` 還原資料到本機。
3. 新主機建立自己的 `machine-profile.json`，設定 `role=primary`、`databaseMode=read_write`。
4. 在新主機重新建立上述任務，先保持暫停。
5. 執行店鋪核對及一批最多20筆的小型讀取，確認資料庫可正常增量寫入。
6. 新主機任務改為 `ACTIVE`；舊主機保持 `secondary/read_only`，不得重新啟用同名採集任務。

任務重建時不得複製舊電腦的聊天 ID、瀏覽器 target、Cookies、API Key 或紫鳥登入狀態。這些都必須在新電腦重新建立或登入。
