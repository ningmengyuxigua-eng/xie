# 資料驗證與隔離規則

## 通用入口規則

所有來源資料先進暫存區。只有同時滿足 Key、型別、期間和關聯規則的資料才能進正式表。

每筆資料必須帶有：

- `store_id`
- `run_id`
- `observed_at`
- 來源 URL或來源檔
- 解析器版本

## 驗證結果

- `accepted`：可寫入正式表。
- `quarantined`：原始資料完整保存，但不進正式分析。
- `rejected`：來源不屬於目標店鋪、資料已損壞或無法解析。

## 商品與規格

- `product_id` 必須為非空數字字串。
- 同一批次內 `store_id + product_id` 必須唯一。
- 每個商品至少有一個 `variation_id`。
- `store_id + product_id + variation_id` 必須唯一。
- 同一 `variation_id` 不得對應多個商品。
- SKU 只作屬性；SKU 重複不阻止寫入，但不得用於身份關聯。
- 商品名稱和規格名稱變更建立新版本，不更換身份 Key。

## 廣告

- `manual/{id}` 標準化為 `single_product`。
- `manual-mpd/{id}` 標準化為 `product_group`。
- 單品廣告必須恰好有一個有效商品關聯。
- 群組廣告必須至少有一個商品關聯，並按頁保存 checkpoint。
- 自動選品在真實活動 ID確認前全部進隔離區。
- 日常分析只接受 `active` 廣告。
- `campaign` 指標與 `product` 指標不能相加。
- 每筆指標必須有 `period_start`、`period_end` 和 `observed_at`。

## 行銷活動

- 折扣和組合活動必須有 `promotion_type + promotion_id`。
- 活動期間必須能解析且 `end_at > start_at`。
- 標示有商品的活動必須取得同等數量的商品 ID；不一致時進隔離區。
- 組合活動商品連結已通過，可寫入原型資料庫。
- 折扣活動只能取得商品數量、不能取得商品 ID時，活動身份可接受，商品關係必須隔離。
- 優惠券內部 ID未確認前使用 `voucher_code + start_at` 作暫存唯一鍵，不進正式長期身份表。

## 訂單與品項

- `order_internal_id` 和 `order_number` 均必須非空。
- `store_id + order_internal_id` 為主關聯 Key；`store_id + order_number` 必須唯一。
- 同一訂單內部 ID若對應不同訂單編碼，或同一訂單編碼對應不同內部 ID，整筆進隔離區。
- 訂單品項必須最終取得 `product_id` 和 `variation_id` 才能進正式同購分析。
- 商品選項貨號和商品名稱不能單獨作關聯 Key。
- 若日後允許 SKU 輔助映射，必須先證明該 SKU 在指定生效期間只對應一個商品／規格，並保存 `match_method` 和可信度。
- 取消、不成立及退款訂單保留狀態，但預設不計入成功同購。
- 訂單資料不保存非必要買家姓名、電話或地址。

## 金額、成本與利潤

- 金額先移除幣別格式，再轉為固定精度數值。
- 訂單折扣和費用在沒有品項分攤規則前只保存在訂單層。
- 商品成本缺失時停用毛利、盈利和損益平衡 ROAS 結論。
- 只有營收和廣告歸因資料時，輸出必須標示為營收效率，不得稱為利潤。

## 期間與滾動指標

- 商品「過去 30 天」數值保存為滾動窗口觀測。
- 廣告統計保存來源 URL中的 `from` 和 `to`。
- 不同期間的指標不得直接相加。
- 相鄰 30 天滾動值之差不得宣告為精確單日值。

## 輸出與上下文

- 驗證器只輸出聚合數量和少量失敗樣本。
- 失敗樣本預設最多 10 筆。
- 模型查詢預設最多 20 行和約 3,000 字元。
- 原始 HTML、完整表格和訂單明細不得直接輸出到對話。
- 超量結果保存到本機，對話只返回路徑、行數及摘要。
