## 廣告驗證

廣告首頁第一頁可見的 20 筆樣本全部標示「進行中」。網址能可靠區分類型：

```text
/portal/marketing/pas/product/manual/{ad_id}
/portal/marketing/pas/product/manual-mpd/{ad_id}
```

抽查結果：

- 單品廣告 `409649493` → 商品 `40834145983`。
- 單品廣告 `399168603` → 商品 `52015619270`。
- 群組廣告 `409611541` → 當前頁可取得 10 個商品 ID。
- 群組廣告 `408093127` → 當前頁可取得 10 個商品 ID。

群組頁面將商品名稱／ID和成效數值分成兩個視覺表格。正式解析器必須按行對齊，不能把群組總計和商品明細重複相加。

## 行銷活動驗證

行銷活動列表能取得：

- 活動狀態
- 活動名稱
- 活動類型
- 商品數量摘要
- 開始及結束時間

進行中促銷組合 `506499042914743` 的詳情頁可直接取得 10 個商品 ID，證明組合活動可建立正式 `promotion_product_link`。

進行中折扣活動 `508428422758448` 可確認：

- 活動狀態為進行中。
- 活動名稱為「品質保證卡」。
- 活動期間為 2026-09-27 23:59 至 2027-01-30 01:00。
- 活動包含 1 個商品。

該折扣頁的普通 DOM 和商品連結沒有暴露商品 ID；進一步驗證已定位只讀端點 `/api/marketing/v4/discount/get_discount_items_aggregated/`。端點以 `promotion_id + offset + limit` 分頁，回傳 `item_id`、`model_id` 和狀態。

活動 `508428422758448` 的小樣本結果為 1 筆：商品 `52217051580`、規格 `307923002527`。兩個 ID 與本地商品主資料中的商品／規格關係一致，因此折扣活動商品 Key 通過驗證。正式同步仍必須每批最多 20 筆，並保存分頁 checkpoint。

## 成本與費用

工作區目前沒有 `.xlsx`、`.xls`、`.csv`、`.tsv` 或 `.ods` 成本資料。商品成本仍需要 ERP、採購資料或人工維護來源。

訂單詳情可提供平台費用和預估進帳，因此平台費用可以從訂單層開始驗證；沒有商品成本前，系統只輸出營收和廣告效率，不輸出盈利結論。

- 店鋪

- 商品規格
- 單品廣告

仍阻塞完整業務資料庫的項目：

1. 自動選品活動的真實 ID。
2. 訂單品項的商品 ID和規格 ID。
3. 商品成本來源。

因此下一階段可以先建立「商品＋規格＋進行中廣告＋折扣及組合促銷」的最小資料庫原型；訂單同購、盈利和自動選品模組保持關閉，直到各自 Key 通過。
