# 長期資料與上下文防卡死設計

## 問題來源

半年資料量本身不是主要風險。以目前 126 個進行中廣告估算：

- 廣告日資料：`126 × 180 = 22,680` 列
- 以目前 1,227 個群組商品明細估算：`1,227 × 180 = 220,860` 列

SQLite 處理這個量級沒有問題。卡死通常來自：一次讀取完整 JSON／HTML、把大量明細送進模型上下文、重複全量抓取、或瀏覽器同時保留太多頁面資料。

## 三層資料架構

### 1. 原始層

- 按日期保存：`store-audit/ad-daily/YYYY-MM-DD/`
- 每次最多 20 筆一批，以 JSONL 寫入，不建立單一巨大 JSON 陣列。
- 原始資料只供追查，不直接交給模型分析。
- 舊原始資料按月壓縮歸檔，不自動刪除。

### 2. 明細資料庫

使用本地 SQLite，透過唯一 KEY upsert：

- 廣告日表：`store_id + metric_date + ad_id`
- 廣告商品日表：`store_id + metric_date + ad_id + product_id`
- 評估結果表：`store_id + metric_date + ad_id + product_id_or_zero + rule_version`
- 同步批次表：`run_id`

需要的索引：

- `(store_id, metric_date)`
- `(store_id, ad_id, metric_date)`
- `(store_id, product_id, metric_date)`
- `(store_id, evaluation_status, metric_date)`

### 3. 聚合層

每日完成後更新：

- `ad_rolling_7d`
- `ad_rolling_30d`
- `ad_monthly_summary`
- `product_ad_monthly_summary`

月報和半年報只查聚合層。需要追查某個異常時，再按日期與 ID 下鑽到明細層。

## 每日增量規則

- 正常每日只抓 D-1，並回補 D-3 延遲歸因。
- 不重新讀取整個月或半年。
- 同一日期、同一廣告 ID 使用 upsert，重跑不增加重複資料。
- 廣告群組只有昨日有曝光、點擊或花費時才展開商品明細。
- 每完成一頁立即保存 checkpoint；中斷後從下一頁繼續。

## 查詢與模型上下文限制

- 模型每次最多接收 20 個廣告／商品明細。
- 工具回傳目標不超過 3,000 字元。
- 月報只返回總花費、總銷售額、ROAS、狀態數量及最多 20 個異常／機會。
- 半年報按月輸出最多 6 行趨勢，不返回 180 天逐日明細。
- 所有排行、加總、分組與篩選先在 SQLite 執行，再把結果交給模型。
- 對話只保存結論、規則版本、資料日期和本地檔案路徑，不保存完整資料。

## 報告讀取方式

### 每日

讀取昨日聚合、近 7 天背景，以及最多 20 個需要處理的項目。

### 每月

直接查 `ad_monthly_summary`，不載入每日原始資料。若某個廣告異常，再單獨查該廣告 30 天資料。

### 半年

讀取 6 筆月彙總與狀態變化。需要趨勢圖時，使用聚合數字生成，不讀取全部明細。

## 回補歷史資料

- 歷史回補按「一天」或「最多 20 筆」執行。
- 每批寫入資料庫並更新 checkpoint 後才執行下一批。
- 回補過程不把資料送進對話，只回報日期、完成頁數、筆數與錯誤數。
- 同一阻塞錯誤連續出現時停止該批，保存進度，不從頭重跑。

## 瀏覽器與 CDP 保護

- 固定復用一個店鋪頁面，不同日期不開多個長期 tab。
- 每次導航後重新取得有效 target，不復用失效 CDP target。
- 頁面讀取與本地分析分離；抓取完成後由本地程序處理。
- 連續錯誤達 3 次停止本批，不進行無限重試。
- 單次頁面輸出超過限制時先在頁面腳本中篩選，不依賴工具截斷。

## 儲存與歸檔建議

- SQLite 明細和月彙總長期保留。
- JSONL 原始資料按月壓縮歸檔。
- HTML、DOM 快照只保留錯誤樣本及必要證據，避免每日永久保存完整頁面。
- 每月執行資料完整性檢查：重複 KEY、缺失日期、無商品映射、異常負值。

## 停止保護

出現以下任一情況時停止當批抓取並保留 checkpoint：

- remote compact 或串流斷線
- CDP target 失效且重新取得 target 後仍失敗
- 連續 3 個頁面或 API 錯誤
- 單批資料超過預設 20 筆
- 回傳內容預估超過 3,000 字元且無法先篩選

不得因停止而清除已完成資料，也不得宣稱網路或 compact 問題已修復。
